================================================================================
PawMatch API Data Structures & Frontend Developer Reference
================================================================================
Base URLs:
- Production Base URL: https://pawmatch-8zwt.onrender.com
- Localhost Base URL:  http://localhost:8000

Common API Response Envelope Standards:
All responses (except raw /health/ endpoints) follow a unified standard JSON wrapper:

Success Envelope (2xx):
{
  "success": true,
  "message": "Detailed success message",
  "data": { ... }
}

Error Envelope (4xx / 5xx):
{
  "success": false,
  "message": "Summary error message",
  "errors": {
    "field_name": [
      "Error description detail"
    ]
  }
}

2. AUTHENTICATION & USER ACCOUNTS ENDPOINTS
================================================================================

--------------------------------------------------------------------------------
2.1 Register New User
--------------------------------------------------------------------------------
- Description:    Registers a new inactive user account and sends verification email.
- HTTP Method:    POST
- Authentication: Public (AllowAny)
- Rate Limit:     Throttle protected (RegisterRateThrottle)
- Production URL: https://pawmatch-8zwt.onrender.com/api/v1/accounts/register/
- Localhost URL:  http://localhost:8000/api/v1/accounts/register/

Request Headers:
  Content-Type: application/json

Request Body:
{
  "email": "user@example.com",
  "password": "StrongPassword123!",
  "confirm_password": "StrongPassword123!",
  "first_name": "John",
  "last_name": "Doe"
}

Response (201 Created):
{
  "success": true,
  "message": "User registered successfully. Please check your email to verify your account.",
  "data": {
    "user": {
      "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
      "email": "user@example.com",
      "first_name": "John",
      "last_name": "Doe",
      "full_name": "John Doe",
      "phone_number": "",
      "profile_image": null,
      "is_email_verified": false
    }
  }
}

Response (400 Bad Request):
{
  "success": false,
  "message": "Validation error message",
  "errors": {
    "email": [
      "A user with this email address already exists."
    ],
    "confirm_password": [
      "Passwords do not match."
    ]
  }
}

    Content-Type: application/json

2.4 User Login
--------------------------------------------------------------------------------
- Description:    Authenticates email and password, returning JWT tokens & user info.
- HTTP Method:    POST
- Authentication: Public (AllowAny)
- Rate Limit:     Brute-force throttle protected
- Production URL: https://pawmatch-8zwt.onrender.com/api/v1/accounts/login/
- Localhost URL:  http://localhost:8000/api/v1/accounts/login/

Request Headers:
  Content-Type: application/json

Request Body:
{
  "email": "user@example.com",
  "password": "StrongPassword123!"
}

Response (200 OK):
{
  "success": true,
  "message": "Login successful.",
  "data": {
    "access": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ0b2tlbl90eXBlIjoiYWNjZXNzIiwiZXhwIjoxNz...",
    "refresh": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ0b2tlbl90eXBlIjoicmVmcmVzaCIsImV4cCI6MTc...",
    "user": {
      "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
      "email": "user@example.com",
      "first_name": "John",
      "last_name": "Doe",
      "full_name": "John Doe",
      "phone_number": "+1234567890",
      "profile_image": null,
      "is_email_verified": true
    }
  }
}

Frontend Developer Note:
- Store `access` token in memory or Axios auth header.
- Store `refresh` token securely (e.g. HttpOnly cookie or secure storage).
- Include header `Authorization: Bearer <access>` in all authenticated API requests.

2.9 Upload / Delete Avatar
--------------------------------------------------------------------------------
- Description:    Uploads avatar image file (via multipart/form-data) or deletes existing avatar.
- HTTP Methods:   POST (Upload), DELETE (Remove)
- Authentication: Required (Bearer Token)
- Production URL: https://pawmatch-8zwt.onrender.com/api/v1/accounts/profile/avatar/
- Localhost URL:  http://localhost:8000/api/v1/accounts/profile/avatar/

POST Request Headers:
  Authorization: Bearer <access_token>
  Content-Type: multipart/form-data

POST Form-Data:
  avatar: <binary image file (jpg, png, webp)>

POST Response (200 OK):
{
  "success": true,
  "message": "Avatar uploaded successfully.",
  "data": {
    "avatar": "https://res.cloudinary.com/demo/image/upload/v1234567890/avatar.jpg"
  }
}

DELETE Request Headers:
  Authorization: Bearer <access_token>

DELETE Response (200 OK):
{
  "success": true,
  "message": "Avatar deleted successfully.",
  "data": {
    "avatar": ""
  }

================================================================================
Note: All RBAC endpoints require `IsAuthenticated` AND `ADMINISTRATOR` role.

--------------------------------------------------------------------------------
3.1 List Platform Roles
--------------------------------------------------------------------------------
- Description:    List all platform roles, display names, and assigned permissions.
- HTTP Method:    GET
- Authentication: Required (Bearer Token + ADMINISTRATOR Role)
- Production URL: https://pawmatch-8zwt.onrender.com/api/v1/rbac/roles/
- Localhost URL:  http://localhost:8000/api/v1/rbac/roles/

Request Headers:
  Authorization: Bearer <access_token>

Response (200 OK):
{
  "success": true,
  "message": "Platform roles retrieved successfully.",
  "data": [
    {
      "role": "ADMINISTRATOR",
      "display_name": "Administrator",
      "permission_count": 45,
      "permissions": [
        "accounts.assign_role",
        "accounts.view_user",
        "pets.create_pet"
      ]
    },
    {
      "role": "SHELTER_STAFF",
      "display_name": "Shelter Staff",
